# 準備画面の連結カードUI（実装済み）

2026-10-29。標準テーマのカード4種類と土台3部品をゲームへ適用。原稿を保管し、2026-10-30に古金・黒鉄・骨白・黒曜石の配信用カラースキン切替を実装。

## 表示

従来の左リスト・中央指示・右予測を、左210pxのカードリストと残り幅の指示編集へ変更する。カードリストは1列。カテゴリ切替はターゲット／条件／アクション／スキル。配置列はターゲット→条件→アクションまたはスキル。内部の判定優先順や全条件ANDのルールは変更しない。

素材は等倍率の拡大・縮小のみ。カードは幅260×高さ約65.63論理px（元の515:130を維持）、接続位置を揃え、隣のカードとの重なり約39.38px（送り約220.62px）。リスト内も元比率のまま幅に合わせる。土台の高さ96px、左端96px・右端48px、中央の反復画像576×96pxはすべて元PNGの75%倍率。長いカード列は行ごとに横スクロールし、カードを変形・折り返ししない。指示行は縦スクロール。PCとスマホ横持ちで同じ1280×720の論理レイアウトを画面へ合わせる既存方式を維持する。

カード見出し・アイコンは承認された素材をそのまま使用し、実際の内容と条件値はHTMLで重ねる。将来の多言語対応や別テーマ完成版では見出しも文字なし素材へ分離する余地があるが、現在の条件値は画像へ焼き込まない。

本文と行番号の位置はart/ui/preparation/layout.jsonで定義する。本文欄は515×130pxの素材上の(x=52,y=64,width=404,height=40)で、リストと指示カードの両方をこの欄の縦横中央に配置する。ボタンのpaddingで位置を決めない。番号は土台上の中心(54,48)へ配置。長い本文は枠内で省略し、配置済みカードのtitleとaria-labelに全文を残す。update-assets.jsが定義をCSS変数としてindex.htmlへ埋め込み、表示倍率が変わっても素材に追従させる。

## 操作

- 配置済み条件をタップすると上部に設定欄を表示。数値のある条件はカード定義の最小／最大／刻みで入力し、変更後に指示へ反映する。数値のない条件は説明のみ。
- リストの条件を選択した場合も同じ設定欄を表示。入力値は次に配置する同名条件へ適用する。この配置前の値は一時的なUI状態で、セーブしない。
- 選択すると配置可能な溝を明るい破線で強調、不可の場所は暗くする。ドラッグ中に有効な配置先へ重なると実線へ変更する。
- 既存のドラッグと「選択→配置先タップ」の両方を維持。条件の入れ替え・行間の移動・対象／実行カードの交換は既存の組み合わせ検証を通し、不可の操作でデータを変えない。
- 行の移動は番号のドラッグで行う。番号を選択して移動先の行をタップする方法も利用できる。↑↓ボタンと操作メニューは配置しない。
- 配置済みカードを左のカードリストまたは「ここへ移動して外す」へドラッグして外す。条件はその1枚、ターゲット・アクション・スキルは対応する行ごと削除。未配置カードは消さない。選択→外すボタンのタップも維持。
- 横スクロール領域の左右端、リストと行一覧の上下端へドラッグした場合は表示を自動スクロールする。ドラッグ開始時には条件設定欄を開閉せず、配置先がずれることを防ぐ。
- 編集は準備中だけ。探索中とひとやすみ中は従来どおり閲覧のみ。

## 探索の予測

下部の「旅の記録」の左に「探索の予測」ボタンを追加。固定の右パネルをなくし、ボタンからダイアログで開く。8／16／24回、再予測、参考値の注意、指示を元に戻す機能は維持する。編集領域にも「元に戻す」を残す。

予測は準備中に自動計算し、「探索の予測」ボタン右へClear見込み・想定ターン数（中央値）・回復余力と終了時HP平均を表示する。初期8試行、各1200ターン上限。指示・装備・能力等が変わった場合は旧結果を消して「計算中…」へ戻し、最新の結果だけを表示する。ダイアログを閉じても準備中の計算は継続し、準備フェイズを離れた場合はキャンセルする。計算失敗時は「予測できません」と表示する。「元に戻す」はその階の準備開始時に記録した指示へ戻す。装備・能力や進行は戻さない。

## 素材・保存・配信

art/ui/preparation/に515×130pxのカード4点と、左128×128・中央768×128・右64×128pxの土台3点を保存。合計230,440bytes（約225KiB）。元のデザインはcard-frame/v1とcard-tray/v3へ保持。scripts/build-card-frames.jsはX/Y別の倍率を廃止し、1つの倍率で枠内へ収めて余白を残す。scripts/build-preparation-assets.jsは追跡対象の部品と定義から再生成できる。Sharpが必要。

update-assets.jsが7点の内容ハッシュをindex.htmlのpreparation-assetsスタイルへ登録し、JS/CSSのハッシュも更新する。比較画像や大きな生成原稿は配信しない。

セーブはv13のまま。既存の指示行・条件値・取得条件・行数／カード数の上限とコストは変更しない。変更した指示は従来の自動保存へ反映する。旧セーブの追加移行は不要。

## 2026-10-30 接続・挿入・ドラッグの修正

接続基準はlayout.jsonのconnection（素材上left=68、right=505、表示幅260px）。等倍率を維持して左右の接続位置を重ねる。常設の空条件カードを廃止し、継ぎ目にマウスをかざすかキーボードでフォーカスした時だけ64pxの追加口を開く。スマホでは条件カードを選択・ドラッグ中にも追加口を開き、スマホでは選択→追加先タップで挿入できる。既存条件を置換せず、指定位置へ挿入する。条件を既存カードへ置いた場合の交換操作は維持。

カード一覧は高さを圧縮しない1列の縦スクロールとし、各カード間に8px空ける。ドラッグ中は画像と本文を含む実際のカードの複製を、掴んだ位置・元の表示倍率のまま追従表示し、元カードを薄くする。終了・キャンセル時に復元する。

セーブv13、カード取得条件・容量・コストは変更なし。予測値は仮の試行結果であり攻略を保証しない。素材画像の追加はない。

接続基準は四隅の飾りではなく凸部の先端と凹部の最奥を使用する。素材上の送り437px、表示上の送り約220.62pxとし、接続中央の横向き♦を次のカードで隠さない。条件→条件・条件→スキル／アクションにも同じ基準を適用する（2026-10-30、参照画像に合わせた修正）。


## 2026-10-30 予測更新・準備画面スキン

予測の再計算キーは配置済み指示・条件値・HP・装備・能力などシミュレーション入力を使用し、ログ・表示用ダメージ・判断文は除外。結果待ちには試行進捗0/8〜8/8を表示し、失敗したキーは破棄して再試行可能にする。1処理区間は8ms経過または24ターンで画面へ制御を戻す。編集中に古い試行が完了しても世代番号で破棄する。詳細には計算開始時点の指示一覧を表示。未配置カードは入力に含めず、指示が違っても同じ結果になる場合があることを表示する。

準備画面のタブ・カード一覧・指示パネル・装備・スキルツリー・状態・下部ボタンを金属枠と暗いパネルへ統一。「スキン」ボタンを押すたび古金→黒鉄→骨白→黒曜石→古金。カードと土台の形状・文字位置・接続位置を維持する。選択はabyss-ui-settings.preparationSkinへ保存し、旧設定は古金。ゲームセーブv13の変更はなし。形式と再生成方法はart/ui/preparation/FORMAT.md。

## 2026-11-03：準備画面の新規イラストと装飾枠

準備画面に新規背景イラスト（石造り・古金・古書・燭台・赤い布）と透過装飾枠を採用。枠は準備画面全体、カード一覧、指示編集パネルに共用し、タブ・探索開始ボタン・下部操作帯の色と陰影を合わせる。文字・カード・透過オーグメント・操作位置・タブ構成は維持する。ヒントと下部操作には枠の太さに合わせた左右余白を付ける。

背景1440×810、枠512×512のWebP2点で約163KiB。画像の縦横比は保持。枠は48pxの9分割から角を固定し辺をrepeatで接続、主枠20px／内部パネル16px。装飾はpointer-events:noneの疑似要素で表示し、ドラッグ・スクロール・クリックを遮らない。古金／黒鉄／骨白／黒曜石の既存スキンに追従する。横向きスマホもPCと同じ構成。素材と再生成手順は[preparation-decor/v1](../../art/ui/preparation-decor-v1/README.md)。
