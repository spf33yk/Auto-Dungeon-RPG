# 準備画面へのカード・土台導入案

採用後の現行実装はPREPARATION_UI.mdを参照。カードリスト1列、予測を旅の記録左のボタンから開く、条件設定欄、溝の強調を実装済み。↑↓と行操作メニューは設けずドラッグを利用。以下は提案時点の履歴で、未採用のパネル開閉・スキン設定等を実装済みとは扱わない。

2026-10-29。提案段階。今回実施したのは素材の余白・はめ込み表現の修正まで。ゲームへの組み込みと以下のUI変更は未実施。

## 修正した素材

card-tray/v3を使用。カード列の端の余白を制作寸法で約8pxへ寄せ、不要な右端の空き枠を削る。カード倍率を30%で固定し、列追加は252pxずつ土台を延長する。上の縁と下の縁の前景レイヤーをカードより後に描き、溝に収まる表現にする。土台自体の高さは全テーマ128px、行間は8px。

## おすすめの画面構成

- 上部：現在のフロア、Lv、HP、記憶の欠片、図鑑・Optionを維持。
- タブ：探索指示／装備／スキルツリー／状態を維持。
- 探索指示タブ：左にカード一覧、中央に指示の土台、右に探索予測を配置。中央の横幅を最優先にする。
- 中央の各行：左の番号欄をドラッグ用ハンドルにし、カード列を1本の溝へ置く。行の移動・削除は行の右側の操作メニューへまとめる。ただしタップとキーボードでも操作できる常設ボタンを残す。
- 下部：探索を始める／あきらめる／旅の記録と準備中の注意を維持。

カード列は縮小せず、長い行だけ横スクロールする。番号欄は固定し、端に続きの存在を示す矢印を出す。指示行の一覧は縦スクロールする。長い行のために画面全体や探索予測を押し出さない。

スマホ横持ちも基本配置を共通にする案。幅不足時はカード一覧と予測を開閉するパネルにし、編集する中央を広げる案を推奨する。PCと常に3列のパネルを同時表示する方式にするかは未決定。カードと文字を一律縮小して収めることは避ける。

## 実装前に解決する課題

|課題|現在の状態と対応案|
|---|---|
|文字と装飾の分離|現在の確認画像にはカテゴリ名とアイコンが焼き込まれている。本番は文字なしの枠・アイコン・HTMLラベルを分け、条件値や長い名称を読みやすく表示する。CARD_FRAMES.mdの方針を維持する。|
|透明余白と連結位置|PNG全体の幅で並べると余白が空く。カード接続アンカーと実際の配置領域を定義し、土台の長さをカード数から算出する。文字や装飾を横に引き伸ばさない。|
|カードの表示順|現行の準備画面は「条件→対象→実行」、今回の素材例は「対象→条件→実行」。見た目は後者へ統一する案を推奨。上から最初に成立した指示を選ぶこと、複数条件がANDであることは変更しない。表示順の採用は未決定。|
|条件値の編集|HP等の数値編集と許可範囲を残す。条件カードを選んだ際に小さな設定パネルを開き、ドラッグと数値入力を区別する。|
|ドロップ先の判別|通常は浅い溝、配置可能な箇所は輪郭と挿入位置線を表示。無効な対象は理由を表示し、色だけに頼らない。空き枠・未取得・使用可能を区別する。|
|スマホ操作|既存のドラッグと「カード選択→配置先タップ」を両方維持。横スクロールとドラッグが競合しないよう、行番号のドラッグとカード操作を分ける。横方向の端の自動スクロールを追加する。|
|はめ込み表現|土台→選択・配置先の表示→カードとHTML文字→上下の縁の順に重ねる。前景の縁はクリックを奪わず、文字・フォーカス枠・ドラッグ画像を隠さない。|
|行数・カード数の拡張|現行の上限と取得条件を維持。行追加と条件追加を別操作にし、残り枠数を表示する。素材が伸びることをゲームの上限変更と混同しない。|
|既存機能|予測の試行回数・再予測・元に戻す・指示の移動／削除・未取得制限・探索中の編集禁止を残す。状態や装備、スキルツリー、図鑑の入口も削らない。|
|スキンの切替|Optionでカードと土台のスキンをまとめて選ぶ案。外観設定だけを保存し、能力・指示・攻略進行と分ける。保存方法と解放条件は未決定。|

## 推奨する導入順

1. 文字なし枠と連結アンカーを整備し、3枚／5枚・空き枠の静止UIで寸法と読みやすさを確認する。
2. 現行の配置・並べ替え・条件値編集へ接続する。スマホ横持ちのタップとドラッグ、横スクロールを検証する。
3. 全テーマの文字色・選択状態・未取得状態を確認してスキン切替を追加する。

実装時に検証する範囲は、操作後の指示内容、優先順、条件値、予測との一致、編集禁止、既存セーブ、狭い横画面でのドロップとダイアログ。今回の素材修正でこれらが動作確認済みになったとは扱わない。
