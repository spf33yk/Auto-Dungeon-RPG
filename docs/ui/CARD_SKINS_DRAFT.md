# 連結カード・土台のスキン方式（設計案）

土台の現行素材はcard-tray/v3。余白を詰め、右端を短縮して上下の縁を前景に重ねる。art/ui/card-tray-v3/FORMAT.mdに素材定義、docs/ui/PREPARATION_CARD_UI_PROPOSAL.mdに準備画面の変更案・課題を記録。ゲームへの適用は未実施。

土台の現行制作基準はcard-tray/v2（art/ui/card-tray-v2/FORMAT.md）。全スキンで同じ枠・番号欄・装飾の外形を共用し、色と内側の材質だけを交換する。下記v1の原稿・方式は保管用の履歴。v2は列が増えてもカードと装飾を縮小せず、中央の幅だけを追加する。

2026-10-29。ユーザーが気に入った連結形状を維持し、カードフレームと土台の外観をセットで切り替える方針。今回は土台の画像サンプルと設計整理のみで、ゲームへの実装はまだ行わない。

## 共通テーマ

|ID案|表示名案|カードと土台の材質|
|---|---|---|
|classic|標準|古びた黒鉄・真鍮|
|black-iron|黒鉄|鋼・控えめな銀色の縁|
|bone-parchment|骨白と羊皮紙|象牙色・羊皮紙・古い金具|
|obsidian-runes|黒曜石と魔法刻印|黒い石材・発光する刻印と結晶|

既存4テーマを基本セットにする案。カードと土台を一緒に切り替え、スキンごとに形状や接続位置を変えない。背景に応じて文字色・コントラストは変えてよい。

正式名称と意味色は全テーマ共通：青＝ターゲットカード、黄＝条件カード、紫＝スキルカード、赤＝アクションカード。「コンディションカード」など別表記を混在させない。ターゲットは先頭、条件は中間、スキル／アクションは末尾という形状の役割を維持する。

カード4種類の四隅は、card-frame/v1の単一♦部品を共通40×40px・共通座標で配置する。左右の上端と下端を揃え、見出し内部などに余分な♦を置かない。「♦あり」と「四隅の♦だけなし」を別保存する。接続部の♦は両方に残す。以前検討した接続部の横長化と土台の♦変更は今回の素材には適用せず、土台案は保留とする。詳細はart/ui/card-frame-v1/FORMAT.md。

## 土台と拡張

2026-10-29の単体カード修正は `art/samples/card-format-v1/` に別原稿として保存する。カード名上中央の♦を除去し、ターゲット左上・スキル右上・アクション右上を補う。既存の接続部は維持し、土台の修正は今回の対象に含めない。上記の土台・接続部装飾案は今回の4枚への実装済み仕様ではない。ゲームUI・セーブへの変更はない。

- 連結カードをまとめて載せる、奥まった横長の溝を1指示行分の土台とする。3枚固定の穴にはせず、途中に条件カードが増えても収まる連続した溝にする。
- 横方向は左端・中央繰り返し・右端で組む。外枠の四隅は固定し、直線部分と中央の面だけを繰り返す9分割の考え方を共用する。接続部・角・装飾・カード自体を無理に引き伸ばさない。
- 縦方向は上端・指示行モジュール・区切り・下端で組む。指示行が増えたら行モジュールを繰り返し追加する。
- 全テーマで行高・余白・接続部の位置・切り出し境界を揃える。土台はカードより控えめなコントラストとし、内容・ドラッグ先の判読性を優先する。
- 横のカード列と縦の指示行の両方が増えることを想定する。収まらない場合のスクロール等は実装時に検討し、列追加だけを理由に文字やカードを潰さない。
- 現行の取得条件・カード枠数・指示行数・上限は今回変更しない。画像の拡張性とゲーム内の解放ルールは分離する。

## スキン追加の考え方

土台の素材制作についてはcard-tray/v1のJSON形式を整備し、ID・表示名・画像・番号色を登録して差し替えできるようにした。カードと土台をまとめるゲーム内のテーマ定義、選択画面、解放条件、保存キーは未実装・未確定。

クリア後に既存4テーマ以外のスキンを追加する案を今後の拡張として記録する。通常エンド／TRUE ENDのどちらで解放するか、何を達成すると入手できるか、最初から選べる範囲や初期スキンは実装前に確定する。外観変更のみで、能力・カード効果・乱数・ゲーム難易度を変えない。

## 今回の成果物と保留事項

サンプルはart/samples/card-bases-v1/へ保存。標準・黒鉄・骨白と羊皮紙・黒曜石と魔法刻印の4案。短い連結と長い連結、指示行の追加例、端・中央の部品案を画像で比較する。

内蔵image_genを使用し、各テーマのカード画像を参照する。生成プロンプトは同フォルダPROMPTS.mdへ保存。現段階の画像は比較用のデザイン原稿で、本番の切り出し部品・厳密なシームレス境界・操作状態別画像は未制作。

ゲームコード、現在のUI、選択設定、セーブ形式は変更しない。キャラクターアニメーション制作の保留も継続する。
