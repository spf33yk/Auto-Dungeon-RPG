# キャラクター4方向アニメーション・共通フォーマット

現行：`character-4dir/v1`。骸を最初の適用対象とし、敵・倅にも同じモジュールと定義を使う。
利用者の依頼原文は[REQUEST_4_DIRECTION.md](REQUEST_4_DIRECTION.md)へ改変せず保存する。原文のwall-autotile/v1参照は当時の指定として保持する。現行マップはwall-autotile/v2であり、共通の正方グリッド・足元深度でそのまま動作する。

## 1. 原稿とスプライトシート

- 制作は32×32pxセル。3列×4行、PNG全体96×128px。透明背景、アルファ0／255、最近傍描画。
- 行IDは0=下south、1=左west、2=右east、3=上north。上下左右の順序は全キャラで固定。
- 列IDは0=歩行／待機1、1=歩行／待機2、2=攻撃。攻撃を歩行ループに混ぜない。
- 骸はスケルトン・傷んだ赤いマント・古い剣・暗い雰囲気。元勇者で記憶を失い、息子のもとへ帰ろうとする父親の設定を考慮する。既存キャラ素材は制作入力に使わない。
- キャラの全体をセル内へ収め、x2〜29、y2〜28に描く。足元の基準は全12コマでy29（最後の可視画素はy28）。空セル、足元の跳ね、他セルへの武器のはみ出しを禁止。
- 足の運びとマントの裾で2コマの差を作る。左右の顔の向き、背面に顔がないこと、頭の読みやすさを32pxで検査する。

## 2. ファイル

各キャラをart/characters/固有名/へ置く。sprites-32.pngは配信用かつ編集用の32px原稿。sprites.jsonにformat/version/id/image/tileSize/columns/rows/width/height/directions/anchor/displayScaleを登録する。

| 項目 | 骸の値／役割 |
|---|---|
| format / version | character-4dir / 1 |
| id | mukuro-red-cape-v1 |
| tileSize | 32 |
| columns / rows | 3 / 4 |
| width / height | 96 / 128 |
| directions | [south,west,east,north] |
| anchor | [16,29]。セルの足元中心 |
| displayScale | 1.25。描画上の倍率。素材の解像度は32のまま |
| image | JSONから相対PNG URL＋内容ハッシュ |

テンプレートとJSONスキーマは同じフォルダに置く。汎用ローダーは8〜256pxのセルも検証できるが、本ゲームの制作とビルドは32pxで統一する。行・列の意味を変える場合は版を上げる。

## 3. CharacterAnimation

キャラごとに独立インスタンスを持つ。フィールドx/yは確定グリッド座標、directionは0〜3、stateはidle/moving/attacking。表示フレームは保存モデルと分離する。

- faceTo(x,y)：差分の大きい軸で向きを決定。同じ大きさの斜め・差分ゼロは直前の方向を維持する。
- moveTo(x,y,time,duration)：移動先を保持し、移動開始時に向きを決める。移動中に0/1を切り替え、連続する移動の開始位相を一歩ごとに反転する。完了でidleへ戻り、最後の接地コマを引き継ぐ。毎回コマ0へ戻して同じ足だけを長く見せない。
- attackTo(x,y,time,duration)：対象へ向き、コマ2を1回表示。時間終了後はidleへ自動復帰する。新たな移動入力は攻撃状態を置き換える。
- teleport(x,y,time)：補間と攻撃を解除してidleへ。向きは維持する。
- 歩行の開始位相・最後の接地コマも個体ごとに保持する。攻撃終了とワープでは待機コマ0へ戻す。接地の切替は描画だけであり移動時間・ターン数を変えない。
- sample(time)：描画に必要な位置・方向・状態・コマを返す。実時計を内部で読まず、呼び出し側から時間を受け取る。
- 待機は240msごとに0/1を交互表示。汎用の移動既定は180ms、攻撃既定は140ms。
- ゲームでは移動を既存補間時間に合わせる（1×190ms、2×170ms、4×85ms）。攻撃は1×140ms、2×100ms、4×50ms。描画フレームレートによって一部の瞬間コマを表示できない場合があるが、状態復帰は時刻で決まる。
- 探索休止・ダイアログ・タイトル・準備では視覚時計を進めない。再開で時間を飛ばさない。reduced-motionでは歩行／待機をコマ0へ固定し、攻撃は短いコマ2のまま表示する。

## 4. 描画と戦闘の結合

characterFrame(def,dir,frame)で切り抜き矩形を算出する。characterDrawBoxは足元=(x+0.5,y+1)マスとanchorから描画矩形を計算し、footY=(y+1)×マス表示幅を返す。壁・モンスターと同じ深度基準を使い、アニメーションで足元のソート位置を変えない。正方形のセルを縦へ引き伸ばさない。

ゲーム内では既存の移動補間座標を描画に渡す。方向・状態は確定移動を受けて更新し、主人公の攻撃はそのターンの敵へのダメージイベントから対象方向を取得する。敵の反撃によってflashが上書きされても攻撃を取りこぼさない。連撃は同一ターンの1つの短い攻撃姿勢として表示する。

戦闘判定・ターン進行・ダメージ時刻をアニメーションのために待たせない。乱数・AI・能力値は変更しない。大きい座標移動はワープとして歩行せず配置する。階変更・Load時はidleへ初期化する。

## 5. 骸から他キャラへ追加する手順

1. 固有フォルダへ新規96×128のPNGとテンプレートのsprites.jsonを置き、idを変更する。
2. 原稿を32pxで作成し、4方向・2歩行＋攻撃・共通足元を確認する。高解像度生成原画はart/local-originalsにローカル保管しGitへ含めない。
3. node scripts/build-character-sheet.js art/characters/対象 を実行してPNG寸法・ハッシュを更新。ビルドにはSharpが必要。第3引数にモジュール、第4引数に生成原画を渡せる。PNGだけ更新する場合も同じコマンドでJSONを更新する。
4. loadCharacterSheetで読込し、各キャラごとにCharacterAnimationを作成する。敵は個体単位に持ち、行動イベントをそれぞれのインスタンスへ渡す。倅も同じAPIで操作する。
5. 配信するsprites.jsonをindexへ登録し、node scripts/update-assets.jsと--checkを実行する。現在はdata-heroへ骸を登録。敵・倅への実際の接続と専用素材は次段階。
6. 全12コマ・透明余白・方向・歩行・攻撃復帰・休止・足元・複数個体独立性・ロード不正寸法を検証する。各資料と同じコミットで反映する。

## 6. 今回の制作範囲と保存

骸の専用PNG、主人公の歩行／待機／攻撃、ポートレート、共通制御モジュールを実装。敵と倅の専用素材・死亡／回避／詠唱等の追加モーションは未実装。将来増やす場合は既存3列を勝手に読み替えず別版を設計する。

保存v12を継続。方向・コマ・視覚時計は保存しない。Load時は下向き待機から開始する。既存の階・能力・取得物への移行・補償は不要。描画用に既存仮素材のフォールバックは保持するが、通常表示は新規の骸PNGを使う。

## 7. 歩行素材の受け入れ基準（同じ足が前に残る問題への対策）

コマ全体が異なるだけでは合格としない。マントだけが動いていても、同じ足が前に残ると歩行に見えない。A/Bで骨盤以下の膝・足首・前後の足を入れ替える。

- 正面・背面：長く接地する足が骨盤の反対側へ移る。片方を前へ出したまま膝を少し曲げるだけにしない。
- 西向き：Aで前へ出ている明るい手前側の脚を、Bでは画面右の後方へ曲げ、暗い奥側の脚を画面左へ出す。
- 東向き：Aで前へ出ている明るい手前側の脚を、Bでは画面左の後方へ曲げ、暗い奥側の脚を画面右へ出す。
- [Bコマの技術ポーズガイド](poses/walk-b-guide.svg)は骨盤と脚の位置を示す。完成素材では同じキャラクター・向き・武器を維持する。
- 頭や足元の位置を揃え、足運び以外の横揺れでごまかさない。今回のBは頭の重心をAの0.5px以内へ合わせ、既存パレットを使用する。
- 攻撃を混ぜないA/Bのみの200〜250msループと、実ゲームの1×・2×・4×で確認する。足元の暖色骨画素の重心移動も回帰テストし、マントだけの変更を検出する。
