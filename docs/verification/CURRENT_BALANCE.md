# 個別成長表適用後の通し検証

2026-11-08。基準コミット6683a01上へ、本報告と同時コミットの個別成長表を適用した作業ツリー。実測時のゲームモジュールSHA256をローカルJSONのruntimeHashesに保持。旧一律倍率の成績を現版の値として使わない。

## 結論

通常エンド到達例はあるが、固定の自動準備方針では初回400試行中1回。序盤の厳しさは残っており、個別成長表の採用をもって難易度調整完了とはしない。新しい表は全30種で各星段階に性能差を設けた仮採用バランス。★3をそろえるまでに必要な入手機会と序盤の生存は別の課題。

400試行は同じ100シードを4方針で比較したもの。400個の独立シードでも、人間一般の勝率でもない。固定方針は最適化済みの攻略ではなく、0回の方針がクリア不能だという証明にはならない。TRUE END本編は未実装のため、TRUEの到達率・所要時間は計測できない。

## 方法

実行：node scripts/verify-clearability.js 100 test-results/growth-balance.json

本番newGame／beginExploration／tick／ascend／equipBest／upgrade／chooseAugment／selectChestCategory／chooseChestCardを使用。初期HP54・Lv1・記憶の欠片12・初期6カード・初期装備から開始し、B30は初期指示のまま。開始3択も実際の候補から選ぶ。探索中の指示変更・未所持付与・HP直接変更・敵削除・乱数巻戻し・デバッグ強化を行わない。

準備中は最強装備と所持カードの配置、指示行数と視界の購入だけ。購入UIのない生命／剣技／守護は全試行0段階。各階で配置条件とvalidateSaveを検査。全401試行でdebugUsed=false。星は実際の取得と有効配置から算出し、検証用に直接指定しない。

シードは(1001＋104729×i) mod 10000000、i=0〜99。同じシードを全方針で使用するが、選択によって乱数消費が変わるため後の報酬・戦闘は同一とは限らない。各階2000ターンで打切り。初回成功例のprofileのみ継承してseed＋19の2周目を確認するため、2周目は条件付き標本。

### 自動準備方針

- 共通：取得済みの回復・防御・攻撃スキルを優先。HP条件を所持していれば回復65%以下等に設定。未所持条件は使わない。候補は容量内で上から採用し、最終階段は本編の常設行を使用する。
- 直行：回収行を設けず、宝箱は1000ターン条件なので通常発動しない。
- 回収：取得済みのハート／泉、宝箱、防具、武器、記憶の欠片を回収する指示を候補へ追加。
- テーマ：回収を基に、所持オーグメントと同テーマのスキルを報酬で選びやすくし、残り枠へ同テーマスキルを追加。
- 敵待機：テーマ方針を基に、隣接条件の取得後「敵＋相手と隣接＋1ターン待機」を最優先。敵操作一般を代表する構成ではない。

オーグメントは吸命・防御・致命傷耐久等を優先する固定点数、テーマ方針では所持スキルとの一致も加点する。全点数・手順はスクリプト内で再現できる。

詳細JSONはローカルtest-results/growth-balance.json。軽量な[試行CSV](current-balance.csv)と[集計JSON](current-balance-summary.json)を保持。計算時間は約113秒で、ゲーム内時間ではない。

## 成功例と時間

テーマ重視・seed5132722で、30階を2837ターンで通常エンドまで到達した。探索だけなら公称420ms÷速度で1倍速約19.9分、2倍速約9.9分、4倍速約5.0分。準備29回を各30〜60秒、その他の映像・操作を2分と仮定すると、成功した1周は1倍速約36〜51分、4倍速約21〜36分。

準備時間は実測ではなく、失敗・再挑戦・離席・処理落ちを含まない。成功1件から一般的なクリア時間や平均再挑戦回数を推定しない。

成功例から派生する2周目seed5132741はB29・130ターンで死亡、手紙なし。2周目地上到達0/1で、周回難易度やTRUEの時間を評価するには不足する。
