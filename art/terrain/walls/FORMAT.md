# ステージ壁マテリアル制作フォーマット

現行：制作入力 `wall-material/v1`、配信定義 `wall-autotile/v2`。32px基準。
壁・通路入口をひとつのマテリアルとして制作し、別材質の入口を後から重ねない。
旧4方向接続・16パターンは維持する。床は別素材のまま、壁と同じ模様を使わない。

## 1. 固定する構造

| 項目 | 規則 |
|---|---|
| グリッド | 正方形。移動・当たり判定は変更しない |
| 基準マス | 32×32px |
| 壁チップ | 32×56px。上面32px＋正面24px、rise=0.75 |
| 視点 | 上面と正面を持つ擬似立体。左上光源、右側は暗くする |
| 接続 | 北1・東2・南4・西8。斜めは無視。マップ外は壁 |
| 壁内部15 | 全域不透明、縁と正面を付けず壁上面で埋める |
| 入口 | 壁と同じPNG・32×56矩形・投影先・暗色処理。独立した材質／高さを持たない |
| 床 | 大きめの水平な石板等。壁上面の小さい密な石積みと区別する |
| 前景壁 | 真上が床なら自分の1マス内に収める。歩行床へ張り出さず、体を隠さない |
| 保存 | 見た目のみ。保存v12・移動・視界・MAP公開範囲は変更なし |

接続番号：単独0、端1/2/4/8、直線5/10、L字3/6/9/12、T字7/11/13/14、内部15。

## 2. 面と明暗の設計

- 上面は暗く密な構造材にする。地下墓所では小さい矩形の石積みを用い、床の丸い大石・割れた石板を流用しない。
- 正面は横積みの段・細い目地・厚みを読める明るさにする。地下墓所の配信PNGでは、正面の代表領域のRGB合計平均を上面の1.35倍より大きくする。
- 南が床のチップだけに正面と上面境界の2pxの稜線・影を描く。北・東・西の未接続側だけ縁を描き、つながる側には外枠を付けない。
- 15番は塊の内部であり、床ではない。黒穴・透明穴を作らず、繰り返し境界に四角い外枠を付けない。
- 視界外の暗色はPNGへ描き込まず、実行時の共通暗色処理で壁と入口をまとめて暗くする。
- 発光、彫像、柱等の装飾はこの構造材へ混ぜない。必要なら別の装飾レイヤーとして将来定義する。

## 3. 制作ファイル

各ステージのフォルダには次を置く。

| ファイル | 用途 |
|---|---|
| material.json | 固有id、zone ID、原稿、色調倍率を指定する制作入力 |
| surfaces-32.png | 64×32。左32×32＝上面、右32×32＝正面の専用原稿 |
| autotile-32.png | 配信用。16壁＋4入口を同じパレットで出力 |
| tileset.json | wall-autotile/v2。画像ハッシュと全矩形を登録 |
| ARTWORK.md | 生成方法・原稿・調整・制作上の判断を記録 |

`wall-material-v1.template.json` を複製する。tileSize=32、rise=0.75、cap=[0,0,32,32]、front=[32,0,32,32]、light=north-west、entranceMode=integratedは共通。capGain／frontGain／bevelGainは0より大きく2以下。地下墓所は0.78／1.12／1.45。入力画像は64×32を検証する。

配信側は `wall-autotile-v2.template.json`、編集支援は両形式のschema.json。materialにcapPixels=32、facePixels=24、共通光源・入口方式を必須とする。tilesは0〜15の16キー、entrancesは下記4キーを必須とし、どちらも32×56矩形の配列。PNG内の配置はJSONで管理し、将来の並べ替えも可能。

現行アトラスは128×280（4列×5行）。最初の4行＝番号0〜15、最後の1行＝入口4種。画素のアルファは0／255。

## 4. 通路入口の統一規則

入口検出は既存の1マス通路の肩の壁だけを対象にする。床には描かない。

| 名前 | 対象 | 素材の範囲 |
|---|---|---|
| leftJamb | 縦入口の左の壁 | 壁の右端3px |
| rightJamb | 縦入口の右の壁 | 壁の左端3px |
| lintel | 横入口の上側の壁 | 正面の先頭3px（y32〜34） |
| threshold | 横入口の下側の低い壁 | 先頭2px（y0〜1） |

入口は同じ正面原稿から作る控えめな継ぎの表現で、独立した大きな柱や別色の笠石を置かない。透明余白を残した32×56セルとして壁の上に重ねる。重ねる先はwallDrawBoxが返す壁と同じ矩形。旧32×32入口を32×56へ引き伸ばす処理はゲームから除外する。

## 5. ビルドと追加手順

1. 新ステージのフォルダへmaterial.jsonと専用64×32原稿を置く。idとthemesを実在するzone IDに変更する。
2. `node scripts/build-wall-autotiles.js art/terrain/walls/対象` を実行。Sharpが制作時のみ必要。第3引数でSharpモジュールを指定できる。第4引数を指定したときだけ高解像度原画から64×32原稿を作り直す。
3. ビルドは原稿の外周2pxを避け、折り返し端4pxをなじませる。接続辺を同値類として共通化し、入口を同じ原稿・パレットから生成する。PNGとJSONのハッシュを更新する。
4. index.htmlのdata-wallsへJSON URLを追加。具体的なzone IDは共通既定 `*` より優先。同じzoneは後勝ち。入口のURLを別に登録しない。
5. `node scripts/update-assets.js` と `--check` を実行する。
6. 関連テストと、部屋四辺・1マス通路・L/T字・入口4方向・前景壁・暗色での画面確認を行う。全16接続、辺の画素一致、透明余白、正面の明暗差、同じ投影先を検証する。
7. SPEC・SYSTEM_DESIGN・DESIGN・素材一覧・検証記録を同時更新する。

## 6. ステージごとの材質方針

以下は専用素材を作る際の制作方針であり、未制作分を実装済みとは扱わない。

| エリア | 材質方針 | 状態 |
|---|---|---|
| 忘れられた地下墓所 | 暗い小石積みの上面、灰褐色の横積み正面 | 今回適用 |
| 苔むした水路 | 湿った青灰色の石、下部に湿気 | 専用原稿未制作 |
| 崩れた鉱山 | 角のある岩盤、横方向の地層 | 専用原稿未制作 |
| 燃え盛る炉跡 | 焼けた煉瓦、煤の付いた上面 | 専用原稿未制作 |
| 凍てついた聖堂 | 冷たい灰青色の切石、薄い霜 | 専用原稿未制作 |
| 封じられた書庫 | 整った石組み、落ち着いた灰紫 | 専用原稿未制作 |

専用素材未登録のエリアは共通既定を使う。ステージを追加するたびに寸法や入口構造を作り直さず、共通投影・接続・光源を保って専用原稿と色調を更新する。上記以外の将来エリアも同じ手順。

## 7. 旧形式

wall-autotile/v1とwall-parts/v1は互換読み込みのみ維持する。旧入口entrance-parts/v1は保管用で、現行ゲームの読込・描画には使わない。旧資料はWALL_AUTOTILE_V1.md・WALL_PARTS_V1.md。原画の高解像度版はart/local-originalsへ保管しGit対象外。制作・配信は32px基準を継続する。
